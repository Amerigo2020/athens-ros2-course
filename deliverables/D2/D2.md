## D2.1: Master/slave control node and service

[Assignment index](../INDEX.md) | [Test results](#d2-1-tests) | [Evidence](#d2-1-evidence)

### Assignment and source

- Current `Athens2026_ROS2.pptx`: slides 92-93.
- Older `Athens_ROS2_Course.pptx`: slides 106-107; position diagram 109.
- Original scaffold: [8_stm_control_node_master_slave.py](../../reference/templates/8_stm_control_node_master_slave.py), upstream revision `cf9e122904ebcb55d336aa7e82d0760bc94cbb07`.
- Status: **Implemented; ROS/hardware verification pending**.

Create STMSetControlType with control_type, kp, kd and success response (D2.1.1); implement the control node with two state subscriptions, one control publisher, service and group parameters (D2.1.2). Use mode 1 for the onboard position setpoint. Stop is mode 0.

### Team implementation / checkpoint

[src/stm_station/stm_station/control_node.py](../../src/stm_station/stm_station/control_node.py); [src/stm_interfaces/srv/STMSetControlType.srv](../../src/stm_interfaces/srv/STMSetControlType.srv)

Runnable stage/configuration preserved in the current tree. These checkpoints were reconstructed for traceability, not presented as previously observed historical progress.

### Execution

[Prepare the Jazzy environment and ports first](../SETUP.md). Each long-running command needs its own prepared terminal. Start recording before the demonstration, and finish it with Ctrl+C. Only one serial stage may access each physical device at a time.

```bash
# Start both custom bridges first (see ../SETUP.md); example partner group 2.
ros2 run stm_station stm_control_node --ros-args -p master_group_id:=7 -p slave_group_id:=2
# Other prepared terminals:
ros2 node info /stm_control_node
ros2 interface show stm_interfaces/srv/STMSetControlType
ros2 service call /stm_setcontrol_type stm_interfaces/srv/STMSetControlType "{control_type: 1, kp: 1.0, kd: 0.0}"
ros2 service call /stm_setcontrol_type stm_interfaces/srv/STMSetControlType "{control_type: 0, kp: 0.0, kd: 0.0}"
ros2 service call /stm_setcontrol_type stm_interfaces/srv/STMSetControlType "{control_type: 99, kp: 0.0, kd: 0.0}"
ros2 bag record -o bags/d2_1_run01 /group_7/stm_state /group_2/stm_state /group_2/stm_control
rqt_graph
```

D2 commands here use the standalone root service /stm_setcontrol_type. With the D3 combined launch it is /group_7/stm_setcontrol_type instead. Partner group 2 is an example, not our team ID.

### Acceptance and hand-in

1. Controller has two state subscribers, one slave command publisher and requested service.
2. Mode 1 passes master position and kp to the slave and the slave tracks physically.
3. Mode 0 stops; invalid mode returns success=false and stops.
4. Stopping master feedback disarms within state_timeout; restoring feedback requires a new service request.

Record observed results in test results section and attach accessible evidence in evidence section. Implementation, verified operation and actual submission are separate statuses. Follow the lecturers' upload/live-demo requirements.

## D2.2: Host position P control (starred extension)

[Assignment index](../INDEX.md) | [Test results](#d2-2-tests) | [Evidence](#d2-2-evidence)

### Assignment and source

- Current `Athens2026_ROS2.pptx`: slides 95.
- Older `Athens_ROS2_Course.pptx`: slides 109 (position controller under D2.1).
- Original scaffold: [9_stm_control_node_master_slave_poscontrol.py](../../reference/templates/9_stm_control_node_master_slave_poscontrol.py), upstream revision `cf9e122904ebcb55d336aa7e82d0760bc94cbb07`.
- Status: **Implemented; ROS/hardware verification pending**.

Close the position loop inside the ROS controller using both encoder positions. Compute PWM = kp * (master_position - slave_position) and saturate. This is a separate configuration/test of the shared controller, not a separate historical code submission.

### Team implementation / checkpoint

[src/stm_station/stm_station/control_node.py](../../src/stm_station/stm_station/control_node.py) mode 2 with kd=0; protocol.feedback_pwm

Runnable stage/configuration preserved in the current tree. These checkpoints were reconstructed for traceability, not presented as previously observed historical progress.

### Execution

[Prepare the Jazzy environment and ports first](../SETUP.md). Each long-running command needs its own prepared terminal. Start recording before the demonstration, and finish it with Ctrl+C. Only one serial stage may access each physical device at a time.

```bash
# Both custom bridges must already be running.
ros2 run stm_station stm_control_node --ros-args -p master_group_id:=7 -p slave_group_id:=2 -p pwm_limit:=25.0
# Separate terminals, example gain to tune:
ros2 service call /stm_setcontrol_type stm_interfaces/srv/STMSetControlType "{control_type: 2, kp: 1.0, kd: 0.0}"
ros2 topic echo /group_2/stm_control
ros2 bag record -o bags/d2_2_run01 /group_7/stm_state /group_2/stm_state /group_2/stm_control
# Stop:
ros2 service call /stm_setcontrol_type stm_interfaces/srv/STMSetControlType "{control_type: 0, kp: 0.0, kd: 0.0}"
```

D2 commands here use the standalone root service /stm_setcontrol_type. With the D3 combined launch it is /group_7/stm_setcontrol_type instead. Partner group 2 is an example, not our team ID.

### Acceptance and hand-in

1. Published mode is 2 (firmware PWM), not onboard position mode.
2. PWM follows proportional position error with correct sign and configured saturation.
3. Physical error decreases; record actual kp, units, limit and response.
4. Feedback loss stops/disarms; graphs compare master and slave encoder trajectories.

## D2.3: Host impedance PD control (starred extension)

[Assignment index](../INDEX.md) | [Test results](#d2-3-tests) | [Evidence](#d2-3-evidence)

### Assignment and source

- Current `Athens2026_ROS2.pptx`: slides 96-97.
- Older `Athens_ROS2_Course.pptx`: slides 110-111 (D2.1.5 extra points).
- Original scaffold: [10_stm_control_node_master_slave_impedance_control.py](../../reference/templates/10_stm_control_node_master_slave_impedance_control.py), upstream revision `cf9e122904ebcb55d336aa7e82d0760bc94cbb07`.
- Status: **Implemented; ROS/hardware verification pending**.

Extend the position loop with measured velocity error: PWM = kp * position_error + kd * velocity_error. Use kd consistently even though the original template also refers to kv. Compare behavior to D2.2 at recorded gains.

### Team implementation / checkpoint

### Execution

```bash
# Both custom bridges must already be running.
ros2 run stm_station stm_control_node --ros-args -p master_group_id:=7 -p slave_group_id:=2 -p pwm_limit:=25.0
```
